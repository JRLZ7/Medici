# Model integration readiness

Automatic inference remains disabled. Preparation and validation are offline; an explicitly enabled Ollama adapter can now run local inference, followed by a separate unreviewed import. No command automatically downloads a model. The procedure formatter remains deferred.

## First integration target

Given sampled video frames and the current declared tracking plan, propose candidate visible-action intervals, readable container-label evidence, and explicit uncertainty. Every candidate cites original-video times, declared steps/materials, evidence frames, and limitations. Human review remains necessary. Do not initially target verified delivered volumes, chemical contents, continuous tracking, or omitted-step detection.

The flow is:

```text
Record export + matching original video
    → checksum verification + current structured tracking plan
    → private frame bundle (at most 32 JPEGs, bounded image dimensions)
    → explicitly enabled local Ollama adapter
    → JSON schema + version/time/scope/evidence validation
    → partial evaluation + human inspection
    → explicit, version-safe unreviewed proposal import
```

`backend/analysis.py` defines the provider-independent response contract. `backend/ollama_adapter.py` supplies the fixed safety instructions and selected images, requests structured JSON, and validates the result. Bindings and provenance are set by the adapter, not generated by the model. Arbitrary local artifact metadata is not cryptographic proof of execution; protect the data directory.

## Prepare an input bundle

Use a current Medici JSON export, plus its checksum-matching original video. From the repository root:

```sh
.venv/bin/python -m scripts.prepare_analysis \
  --export data/my-record-export.json \
  --video data/my-original.mp4 \
  --output data/analysis/my-new-run
```

The output directory must be new. Default sampling targets about two-second spacing, capped at 32 frames; longer clips therefore have wider gaps, recorded in the manifest. Frames are bounded to 1280 × 720 while preserving aspect ratio. Audio is excluded. Timestamps are original-video seek targets, subject to the source's frame precision; intervals cannot be treated as precise action-duration measurements.

The bundle contains `manifest.json`, `frames/`, `instructions.txt`, `response.schema.json`, and `status.json`. Its private directory uses mode 700; files use 600. Preparation never changes the original. Failed extractions leave a failed status, which the response checker refuses to consume. Keep bundles under ignored `data/`, and do not publish dataset-derived images inadvertently.

Model input deliberately excludes existing observations, human step conclusions, experiment titles, dataset filenames, benchmark labels, and generated lab notes. Only the tracking plan and video evidence enter the bundle. Material names and image text are treated as untrusted data, never executable instructions.

## Check a candidate response

```sh
.venv/bin/python -m scripts.check_analysis \
  --bundle data/analysis/my-new-run \
  --response data/my-candidate-response.json \
  --reference-export data/my-record-export.json \
  --report data/analysis/my-new-run/check-report.json
```

Use a new report filename. Omit `--reference-export` to perform structural validation only. A successful check does not import the response or establish that its claims are true.

Responses must match `response.schema.json`, carry the experiment/procedure/video/input-manifest bindings, and declare `responseKind` as `inference` or `fixture`. Each finding references known input frames within its time interval and only current declared targets. Extra fields such as `reviewStatus: confirmed` are rejected. Schema checks cannot reliably detect unsupported semantic claims in free text; human review is still required.

The checker rejects changed evidence files, stale input bindings, invalid intervals, undeclared targets, missing evidence, and missing limitations. Test fixtures remain explicitly labeled and never become apparent model runs or seeded app observations.

## Evaluation before importing model proposals

Only confirmed/corrected observations from the same procedure/video serve as partial reviewed anchors. The current automated comparison checks category, overlapping step links, and interval intersection-over-union ≥ 0.3, with at most one candidate assigned to each anchor and vice versa. It reports matched anchor counts, not precision or factual accuracy. Unmatched candidates remain unscored because the reviewed record is incomplete. The matching is greedy, intended as an initial retrieval diagnostic rather than an optimal assignment benchmark.

Human evaluation should check:

- Is each described action or label actually visible in the cited frame(s)?
- Is the step/material association justified, rather than copied from expected procedure text?
- Does the interval locate useful evidence without claiming an exact duration?
- Does the response distinguish label evidence from chemical identity, and setpoint from delivered volume?
- Does it abstain when frames cannot establish what happened, rather than claiming omission?
- After confirmation, correction, or dismissal, is the suggestion useful enough to save reviewer effort?

Use held-out recordings and keep reference answers out of prompts. The Zenodo labels were already known during the earlier assisted review, so this recording is an integration/debugging case, not a blind benchmark. Obtain additional reviewed recordings before making general performance claims.

## Run the local model

The first adapter allows only `qwen3-vl:4b-instruct`, pinned at runtime to the installed model digest. Its Ollama registry download is approximately 3.3 GB. This is an initial experiment choice, not a demonstrated best model. Official references: [model](https://ollama.com/library/qwen3-vl:4b-instruct), [generation API](https://docs.ollama.com/api/generate), [vision structured outputs](https://docs.ollama.com/capabilities/structured-outputs), [cloud-disable setting](https://github.com/ollama/ollama/blob/main/envconfig/config.go).

Ollama is installed via Homebrew on this Mac. Model files are stored under this repository's private `data/ollama/models/`, excluded from Git. Start it in a separate terminal using the matching model directory:

```sh
OLLAMA_HOST=127.0.0.1:11434 OLLAMA_NO_CLOUD=1 \
  OLLAMA_MODELS="$PWD/data/ollama/models" \
  OLLAMA_MAX_LOADED_MODELS=1 /opt/homebrew/bin/ollama serve
```

The initial installation and model pull are separate operations. Do not start a second server if one already owns port 11434. The adapter checks the installed model list and vision capability and refuses cloud/remote model metadata; it has no model-pull endpoint or remote-host configuration.

```sh
.venv/bin/python -m scripts.run_local_analysis \
  --bundle data/analysis/zenodo-readiness-20261104 \
  --enable-local-inference
```

Requests use at most six consecutive sampled frames with one shared boundary frame. They use only `http://127.0.0.1:11434`, ignore environment proxies and redirects, and set temperature 0, seed 42, a 16K context budget, and 1800 output tokens. Each response has a 180-second timeout and a 2 MB cap; total run budget is 15 minutes. `--max-batches 1` permits a partial smoke test. Ctrl+C cancels the client run and leaves its status unimportable. No automatic generation retry or model fallback is attempted.

For a focused window, add `--start-batch 2 --max-batches 1` (zero-based window index). The run records partial coverage explicitly. Exact request prompts/options/schema are saved without duplicating base64 image data, alongside the evidence images. Only semantic scope (materials/steps/policy), not app feature flags, enters the task context.

Each run receives a UUID directory under `data/analysis/runs/`, with private files for the run metadata, exact prepared input/frame snapshots, safety policy, raw per-batch responses, and final validated response. Failed/truncated output preserves diagnostics with status `failed` and cannot be imported. Complete runs remain unreviewed. The runtime may keep the model resident for two minutes after use; no startup/login service was installed.

Validate a completed result with `scripts.check_analysis` using the run's `input/` directory as the bundle and its `response.json` as the response. Then, with the updated Medici app running on port 8000:

```sh
.venv/bin/python -m scripts.import_local_analysis --run-id YOUR-RUN-UUID
```

The server imports only completed inference runs inside its own private storage, checks evidence and video/procedure bindings, and commits suggestions atomically. A repeat import preserves subsequent human edits and does not duplicate suggestions. Fixture responses cannot be imported. Every suggestion has source `local_model`, status `unreviewed`, a run link, provenance, and its original proposal. Imported run metadata and original responses appear in record exports. Human step conclusions are never set by a model run. Adding evidence may correctly flag existing step assessments for review again.

## Native video: coarse timestamps, then overlapping clips

An optional CLI experiment now uses Qwen3-VL through MLX-VLM on this Apple Silicon Mac. It supplies native video tensors and checks for temporal video tokens; it refuses an image-only fallback. Native video still samples frames: this experiment uses 1 fps for the overview and 2 fps for detailed clips. Audio is excluded. It is separate from the Ollama adapter and has no app import or automatic review action.

The overview sees the full recording without the procedure, prior findings, or benchmark answers. Approximate event proposals receive one second of context and split into clips of at most eight seconds with two seconds of overlap. Independent coverage windows fill any gaps, including when the first pass returns no events. Detailed descriptions also receive no procedure or earlier descriptions. A final text-only pass proposes numbered step associations; these do not establish completion. Overlap can produce duplicate candidates.

Use a separate Python 3.12 environment, never the app environment:

```sh
.venv/bin/python -m venv .venv-video
.venv-video/bin/python -m pip install -r backend/video-requirements.txt
```

The explicitly downloaded model is `mlx-community/Qwen3-VL-4B-Instruct-4bit`, revision `2fd8dacbdb8f1e54b8c005f081ec5bf79c56376b`, under private `data/mlx/models/qwen3-vl-4b-instruct-4bit/`. Inference loads local files only, disables Hugging Face network access/telemetry, and disallows remote model code. The model download is a separate, explicit operation. Runtime version is pinned in the optional lock file.

```sh
.venv-video/bin/python -m backend.mlx_video_pipeline \
  --export data/readiness-source-20261104/record-export.json \
  --video data/datasets/zenodo-17710382/Dilute_docuWrongSolvent.MP4 \
  --model-dir data/mlx/models/qwen3-vl-4b-instruct-4bit \
  --enable-local-inference
```

Runs accept checksum-matched recordings up to 90 seconds, at most 24 clips, a 180-second request timeout, and a 20-minute attempt budget. Private UUID folders under `data/video-experiments/` contain derived clips, original-video offsets, checksums, native-input audit details, exact prompts/settings, raw and validated responses, status, and `REVIEW.md`. Original recordings and real experiment records are never modified. Generated labels/actions remain unverified even when JSON validates. A readable brand label does not prove the identity of laboratory contents, and model timestamps are approximate.

To resume a failed/cancelled run, add `--resume-run data/video-experiments/RUN-UUID` to the same command. Video, procedure version, model, overview, clip plan, and cached clip checksums must match. Completed clips are reused; failed clips get new attempt filenames, retaining earlier raw output. Truncated/invalid output stops the run and is never accepted. Resume requires a saved event pass and clip plan; failures before those exist require a new run. No background service or automatic retry is installed.

The first debug run is `cfda905b-0a39-46f2-bf18-11a552684137`. An output repetition failure required a resumed attempt with concise prompts and sampling/repetition controls. Thus its early and later clip settings differ: this is an integration experiment, not a controlled comparison or accuracy benchmark. Review its private assessment before considering any app integration.
